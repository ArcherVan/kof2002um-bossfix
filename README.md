# kof2002um-bossfix

**《拳皇 2002 UM》(KOF 2002 UM) 玩家选用 BOSS 时的伤害补偿工具。**

不改动游戏文件，在游戏运行时对"伤害落地"指令挂钩，把玩家打出的伤害按可调倍率还原回去。

> **English (short)**: A runtime-only damage multiplier for *The King of Fighters 2002 Unlimited Match* (Steam / Code Mystics port). It hooks the single HP-subtraction instruction, amplifies outgoing player damage by a configurable factor, never touches files on disk, and can be toggled or removed at any time.

## 项目简介

《拳皇 2002 UM》里，玩家如果直接选用 BOSS（Omega Rugal、Krizalid、Clone Zero、Original Zero、Igniz 等），会明显感觉"打得没伤害"。官方对此的处理是**削弱 BOSS 的攻击力**，而 CPU 操作同一个 BOSS 时受到的是**受击减伤**——两套不同的机制。

本项目解决前半段：让你选用的 BOSS 打出正常量级的伤害。

做法是在游戏进程内挂一个钩子（code cave），拦截"HP -= 伤害"这一条指令，在写回之前按倍率放大伤害值。因为只改运行时内存，所以：

- **游戏文件零改动**，EXE 的 MD5 始终不变；
- **随时开关**，一个内存标志位就能在"补偿"和"原版"之间切换；
- **进程退出即消失**，不会留下任何持久化痕迹。

本仓库同时保留了完整的分析记录（[docs/01-原理与机制分析.md](docs/01-原理与机制分析.md)），包括一条重要教训：**最初认定的"×0.5 BOSS 补正"经过运行时实测被证伪**，详见后文。

### 适用对象

| 项 | 说明 |
|---|---|
| 游戏版本 | Steam 版 / Code Mystics 移植版（其他 repack 见[兼容性](#兼容性与环境适配)） |
| 系统 | Windows 10 / 11，64 位 |
| Python | 3.8+（仅用标准库，无需 pip 安装任何包） |
| 权限 | 普通用户通常可用；写入失败时用管理员 |
| 场景 | **仅单机**。不要用于联机对战 |

## 功能特性

| 功能 | 命令 | 说明 |
|---|---|---|
| **一键启动** | `kof.cmd launch` | **启动游戏 + 自动等解密 + 打补丁 + 持续补满气槽**，一条命令搞定 |
| 加载补偿 | `kof.cmd install` | 安装钩子，可重复执行，自带失效检测与自愈 |
| 开启并设定倍率 | `kof.cmd on 2` | 支持一位小数，实时生效，无需重开对局 |
| 关闭 | `kof.cmd off` | 伤害立刻回到原值，钩子仍保留 |
| 查看状态 | `kof.cmd show` / `status` | 开关、倍率、命中计数、双方血量、钩子健康度 |
| 实测伤害 | `kof.cmd watch 120` | 实时打印每次命中的真实伤害值 |
| 录制日志 | `kof.cmd rec 300` | 把伤害序列写入 `hookdmg_log.txt`，用于校准 |
| 卸载 | `kof.cmd uninstall` | 逐字节还原并释放内存 |
| 无限气 | `kof.cmd power patch` | 跳过 1P 的扣气指令，装一次整局有效 |
| 气槽查看/手改 | `kof.cmd power show` / `set 3` | 查看或直接改写双方气槽格数 |
| 环境自检 | `kof.cmd doctor` | 检查系统、Python、权限、配置、版本指纹 |

设计上的几个取舍：

- **只放大"玩家打出去"的伤害**：钩子只在受击方是 2P 对象时生效，CPU 打你的伤害不受影响。
- **无限气只对 1P 生效**：扣气补丁在代码洞里比对受影响的角色对象，只放行 1P，CPU 仍正常消耗气槽——否则对手会无限放超必杀。
- **幂等安装**：重复执行 `install` 不会重复挂钩；检测到旧版或失效钩子会先还原再重装。
- **原字节校验**：钩子安装前比对目标地址的原始指令，版本不符时拒绝改动而不是盲写。
- **零第三方依赖**：只用 `ctypes` + `struct`，不装包、不联网。

## 核心原理与实现思路

### 1. 为什么必须"运行时改"

这一版游戏的可执行文件里，`.text` 段在磁盘上是**加密**的（熵接近 8.0），游戏启动后由加载器解密到内存 `0x401000` 并置为可读写执行。

这意味着：**用十六进制编辑器改 EXE 里的一个字节 = 改密文**，游戏大概率直接起不来。所以任何有效的改动都只能发生在游戏进程内——这也是本项目只提供运行时方案的原因。

好消息是这种改法天然可逆：进程退出，内存回收，一切恢复。

### 2. 这个移植版的代码长什么样

原 PS2 版是 MIPS 代码，Code Mystics 的框架把它**静态重编译**成了 x86。所以反汇编出来的代码有个鲜明特征：MIPS 的寄存器没有落到真实 x86 寄存器，而是**溢出到固定全局地址**（`$v0`、`$a0`、`$a1`、`$ra` 各占一个槽），条件判断结果也先写进一个"结果槽"再取用。

这直接解释了为什么"搜 0.5 浮点常量"这类常规手段全部失败——伤害减半在这个移植版里不是浮点乘法，而是对某个全局槽做一次**右移一位**。

### 3. 伤害落地的唯一入口

整场对战里，HP 的扣减集中在这一条指令上：

```
sub word ptr [eax+0x138], dx      ; HP -= 伤害
```

- `eax` = **受击方**角色对象
- `dx` = 本次伤害
- `0x138` = 角色对象内的 HP 字段（16 位有符号）

这就是钩子的挂载点。它只有一处，所以钩住它等于拿到了**每一次真实伤害**，不需要读屏幕、不需要截屏、不需要猜。

### 4. 钩子怎么工作

安装时申请一块可执行内存（code cave），写入一段机器码，然后把原指令的前 5 个字节替换成一条 `jmp`，跳到 cave 执行，最后跳回原指令之后。

执行流程：

```
pushfd / push ecx / push edx          ; 保存现场
把 (受击方, 伤害, 当前对象槽) 记入环形缓冲   ; 诊断用，共 64 条
若 开关 != 0 且 受击方 == 2P对象:
        ecx = 伤害 × 倍率 >> 8        ; 8 位定点，256 = ×1.0
        写回栈上的 dx                 ; 覆写本次伤害
pop edx / pop ecx / popfd
原指令（被替换的那条）
jmp 回到原指令之后
```

三个实现细节值得说明：

- **倍率用定点数**：`factor` 存为整数，`256` 表示 ×1.0，所以 `1.5`→`384`、`2.0`→`512`，一位小数足够，避免浮点指令污染栈上的标志位。
- **开关与倍率都在 cave 里**：`on` / `off` 只是往 cave 里写字，所以切换是即时的，不需要重新挂钩。
- **自愈识别**：cave 里写了版本标记；`install` 会顺着 `jmp` 找到 cave，校验机器码特征与标记，是自家的就"认领"，是旧版就先还原再重装，指向已释放内存就先修复再重装。

### 5. 为什么最终方案是"落地补偿"而不是"改倍率"

理想做法是找到"玩家选 BOSS 时攻击力下降"的那行代码，把系数改回 1.0。但实测证明这条路走不通（原因见下一节），所以改用等效但更稳的方案：**不改上游计算，只在下游落地时按倍率乘回去**。

优点是：

- 不依赖尚未定位的上游逻辑，现在就能用；
- 倍率可调，可以自己校准到"和 CPU 用同一个 BOSS 时的伤害持平"；
- 风险可控——只动一条指令，且随时可关。

代价是：**它不知道你是不是在用 BOSS**，所以只能靠"只对 1P 攻击生效 + 手动开关"来约束作用范围。

## 已定位的伤害逻辑与修正记录

这一节是本项目最有价值的部分：一个被推翻的结论，以及推翻它的证据。完整版见 [docs/01-原理与机制分析.md](docs/01-原理与机制分析.md)。

### 发现的伤害后处理链

伤害落地之前，会经过一段后处理（`0x628200`–`0x628264`）：

```
伤害 == 0xFF ?  → 改写成 0x7FFF        ; 秒杀哨兵（某些招式用 0xFF 表示必死）
角色对象 +0x11D 的 bit0 置位 ?  → 伤害 >>= 1        （×0.5）
否则 角色对象 +0x0E6 的 bit6 置位 ?  → 伤害 = 伤害/2 + 伤害/4   （×0.75）
```

两档是 **if/else 互斥**的，不会连乘，所以最坏是 ×0.5 或 ×0.75，不存在 ×0.375。

当时的判断是：`+0x11D` bit0 就是"BOSS 惩罚位"，把它置位的指令全局只有一处，NOP 掉就能解除 ×0.5。于是打了一组补丁（4 个 NOP 位点），实机验证字节一致、游戏稳定运行。

### 推翻它的证据

补丁打上之后，用户的反馈是：**伤害完全没有任何变化**。

于是改成在伤害落地处挂钩，逐次记录 `(受击方, 伤害, 当前对象槽)`，共采集 279 次命中。结论很干脆：

| 观测 | 结果 |
|---|---|
| 当前对象槽指向哪一方 | **279 次全部是受击方**，没有一次是攻击方 |
| 伤害序列形状 | `11 → 5 → 2 → 1 → 1 → 1`，随连段递减，最低到 1 |
| 普通角色打一整局 | 同样出现递减 |

也就是说，那条 ×0.5 链处理的是**挨打方吃到的伤害**，属于 2002UM 的**多段命中衰减**（连段每多打一下，伤害按 1/2、3/4 两档往下压，最低压到 1），跟 BOSS 无关。

那组 NOP 补丁的实际效果是"**关闭连段伤害衰减**"——不但没解决 BOSS 问题，反而会让连段伤害偏高、破坏平衡。**它们已被废弃，不再包含在本项目的任何命令里。**

### 修正后的认知

| 机制 | 作用对象 | 状态 |
|---|---|---|
| 多段命中衰减（×0.5 / ×0.75） | 受击方 | 已定位，**未修改**（属正常游戏机制） |
| CPU 用 BOSS 时的受击减伤 | CPU 侧 | 已观察，未修改 |
| **玩家选 BOSS 时的攻击力下降** | 攻击方 | **倍率与代码位置仍未定位** |

第三项就是本项目要对抗的东西。因为没定位到源头，所以采用落地补偿：**不去猜它削了多少，而是让你自己把倍率调到合适**。

### 这条经验值得记住

静态反汇编能告诉你"这里有一次折半"，但不能告诉你"这次折半服务于谁"。**判断一个可疑逻辑到底属于哪一方，最省事的办法是运行时把两边的地址一起打出来对比**——本项目就是这么把结论钉死的。任何"看起来很像"的定位，在实测之前都不算定位。

### 步骤

1. **获取代码**

   ```bat
   git clone https://github.com/ArcherVan/kof2002um-bossfix.git
   cd kof2002um-bossfix
   ```

   没有 git 就下载 ZIP 解压，效果一样。

2. **环境自检**（游戏不用开）

   ```bat
   kof.cmd doctor
   ```

   预期结尾是 `结论：环境可用 ✔`。此时游戏进程一项会是 `[WARN] 未检测到…`，属正常。

3. **（可选）按你的版本调整配置**

   默认值对应 Steam 版。如果你用的是其他 repack，先复制模板：

   ```bat
   copy config.example.json config.json
   ```

   再按 [配置说明](#配置说明) 修改。不确定要不要改，就先跳过——`doctor` 会告诉你字节对不对。

4. **启动并加载**

   最省事的一条（启动游戏 + 免扣气补丁 + 2 倍伤害补偿）：

   ```bat
   kof.cmd launch --dmg 2
   ```

   也可以自己开游戏后再挂：

   ```bat
   kof.cmd install
   kof.cmd on 2
   ```

   看到 `钩子已安装` 或 `钩子已存在，直接认领`，且 `伤害补偿：开   倍率 = 2.00` 即成功。

## 使用

### 一键启动（推荐）

不想记两条命令，直接：

```bat
kof.cmd launch
```

它一次做完：定位游戏 exe → 启动 → 等 `.text` 解密完成 → 装免扣气补丁 → 把 1P 气槽顶到 5 格 →
留在窗口里盯着，气槽一掉就补满，直到你退出游戏。

常用变体：

| 命令 | 作用 |
|---|---|
| `kof.cmd launch` | 启动 + 免扣气补丁 + 持续补满气槽 |
| `kof.cmd launch --dmg 2` | 再叠上伤害补偿（2.0 倍） |
| `kof.cmd launch --no-keep` | 只打补丁，不自动补气 |
| `kof.cmd launch --no-power` | 只启动游戏，不打补丁 |
| `kof.cmd launch --new` | 已有游戏在跑时，仍然再开一个 |
| `kof.cmd launch --exe "D:\...\KingOfFighters2002UM.exe"` | 手动指定游戏路径 |
| `kof.cmd launch --steam` | 走 `steam://` 协议启动（直接起 exe 被拦时用） |

游戏已经在跑时再执行同一条命令，它会认出现有进程、只补打补丁，不会开第二个。
关掉这个控制台窗口不影响已打好的补丁，只是不再自动补气。

### 手动三步

不想让工具代管启动，也可以自己开游戏再挂：

```bat
cd /d <你的仓库路径>
kof.cmd install
kof.cmd on 2
```

顺序不能颠倒——`install` 必须在游戏启动之后。

### 命令一览

```bat
kof.cmd doctor            环境自检
kof.cmd config            查看当前生效的配置及来源
kof.cmd launch            启动游戏并自动打补丁（推荐）

kof.cmd install           加载钩子（游戏须已启动；可重复执行）
kof.cmd on 2              开启补偿，倍率 2.00
kof.cmd on 1.5            自定义倍率（支持一位小数）
kof.cmd off               关闭补偿（钩子保留）
kof.cmd show              查看开关与倍率
kof.cmd status            钩子健康度 + 双方血量
kof.cmd watch 120         实时打印伤害，持续 120 秒
kof.cmd dump              打印环形缓冲里已记录的伤害
kof.cmd rec 300           录制伤害到 hookdmg_log.txt

kof.cmd power show        查看双方血量、气槽格数、免耗气标志

```

### 无限气的两种用法

| 方式 | 命令 | 生效范围 | 何时失效 |
|---|---|---|---|
| **补丁**（推荐） | `kof.cmd power patch` | 跳过三处扣气指令，装一次就一直有效 | 关闭游戏 |
| 写数据 | `kof.cmd power on 5` | 只改当前气槽与标志位 | 游戏重置气槽后 |

补丁把三处扣气指令改成跳转到一段共享代码，代码里比对当前角色是否为 1P，是则跳过扣减、否则照常扣。这样 CPU 不会跟着变成无限气。

---

### 倍率怎么选

| 倍率 | 命令 | 说明 |
|---|---|---|
| 1.0 | `off` | 等同原版 |
| 1.5 | `on 1.5` | 轻微增强 |
| 2.0 | `on 2` | **推荐起点** |
| 2.5 | `on 2.5` | 偏强 |
| 3.0 | `on 3` | 上限，不建议再高 |

建议范围 **1.0 ～ 3.0**。倍率对之后发生的伤害生效，不追溯。

### 校准倍率（约 3 分钟）

倍率是经验值。想精确对齐，用练习模式的伤害数字对比：

1. `kof.cmd on 2` → 练习模式，P1 选你的 BOSS，P2 选血厚的普通角色并让它静止。
2. 固定站位，用**同一招**打 3 次，记下稳定值 `A`。
3. `kof.cmd off` → 换一局，**P2 选同一个 BOSS 由电脑操作**，P1 站着挨同一招，记下 `C`。
4. `A < C` 就调大，`A ≈ C` 就是合适值，`A > C` 就调小。

### 换角色玩之前

```bat
kof.cmd off
```

补偿不区分角色，开着就会放大你打出的所有伤害。

## 配置说明

配置文件为仓库根目录的 `config.json`（UTF-8 JSON）。不存在时使用内置默认值；也可用环境变量 `KOF_CONFIG` 指向任意路径的配置文件。

| 字段 | 默认值 | 含义 | 何时需要改 |
|---|---|---|---|
| `process_name` | `KingOfFighters2002UM.exe` | 进程名，大小写不敏感 | repack 改了 EXE 名 |
| `game_exe` | 空 | 游戏 exe 完整路径；留空则自动扫 Steam 库和工具目录附近 | `launch` 提示找不到游戏 |
| `steam_appid` | `222440` | Steam AppID，直接起 exe 失败时用它走 `steam://` 重试 | 换成别的版本 / 留空禁用重试 |
| `hook_site` | `0x620902` | 伤害落地指令的运行时地址 | 版本不同、`doctor` 报字节不符 |
| `hook_orig` | `66 29 90 38 01 00 00` | 该处原始字节（校验用） | 同上 |
| `hook_back` | `0x620909` | 原指令之后的下一条地址 | 同上 |
| `obj_slot` | `0x21E3414` | 引擎"当前对象"全局槽 | 仅记录用，一般不改 |
| `player_obj` | `0x167D360` | 1P 角色对象地址 | 版本不同导致补偿不生效时 |
| `enemy_obj` | `0x167D580` | 2P 角色对象地址 | 同上 |
| `hp_offset` | `0x138` | 角色对象内 HP 偏移 | 一般不改 |
| `power_offset` | `0x1E3` | 角色对象内气槽格数（0~5） | 一般不改 |
| `power_flag_offset` | `0x1EE` | 角色对象内"免耗气"标志 | 一般不改 |
| `default_factor` | `2.0` | `on` 不带参数时的倍率 | 想固定默认倍率 |
| `log_file` | `hookdmg_log.txt` | 录制日志文件名 | 想换位置 |

地址字段可以写 `"0x620902"` 或十进制整数。改完执行 `kof.cmd config` 确认已生效，`kof.cmd doctor` 确认字节匹配。

**怎么找新版本的地址**：见 [docs/01-原理与机制分析.md](docs/01-原理与机制分析.md) 的定位方法一节。核心思路是用 `dump`/`watch` 拿到真实伤害，再在落地指令附近用原字节特征搜索。

完整矩阵与排查流程见 [docs/03-兼容性与环境适配.md](docs/03-兼容性与环境适配.md)。

### 已确认可用的版本

| 版本 | EXE 大小 | MD5 | 状态 |
|---|---|---|---|
| Steam / Code Mystics（默认配置） | 4,748,304 | `e7a78eb4f724f65f12084bfc6e12420b` | 已验证 |

其他 repack 通常会保留相同的代码结构（同一份 PS2 二进制重编译而来），但加载基址或对象地址可能不同。判断方法：

```bat
kof.cmd doctor
```

`钩子点字节与预期一致` → 直接可用；`钩子点字节不符` → 需要按 [配置说明](#配置说明) 调整。

### 不同 Python 环境的适配

`kof.cmd` 会按顺序探测解释器，命中即可用，**不需要手动配 PATH**：

```
py -3  →  python  →  python3        （各自都要求能 import ctypes）
```

| 环境 | 说明 |
|---|---|
| python.org 官方安装 | 勾选 "Add Python to PATH" 后直接可用 |
| Windows 应用商店版 | `py -3` 通常可用 |
| Anaconda / Miniconda | `python` 命中即可；建议用 `conda activate` 后的环境 |
| 嵌入式/便携版 Python | 把目录加入 PATH，或直接用其 `python.exe src\hookdmg.py ...` |
| 多版本共存 | `py -3` 会挑最新版；需要指定时改 `kof.cmd` 里第一行探测 |

### 路径含中文或空格

支持。`kof.cmd` 全程使用绝对路径并加引号，仓库放在中文目录下也能运行。

### 无管理员权限

除个别系统策略外，普通权限即可读写同用户进程。若 `doctor` 里出现 `ReadProcessMemory 失败`，用管理员身份重开命令行再试。

## 已知限制

1. **只对 1P 位置生效。** 补偿的判定是"受击方 == 2P 对象"，即你作为 1P 攻击时。你在 2P 位置不会生效。
2. **不区分角色。** 它不知道你是不是在用 BOSS，开着就放大所有你打出的伤害。玩普通角色前必须 `off`。
3. **每次启动游戏都要重装。** 改动只在进程内，退出即消失。想让这一步自动化，用 `kof.cmd launch`（启动即打补丁），或把它的快捷方式放进启动项。
4. **倍率是补偿而非还原。** "玩家选 BOSS 时攻击力下降"的确切倍率尚未定位，本工具是用可调倍率逼近，不是精确恢复。
5. **不改变 CPU 侧行为。** CPU 用 BOSS 时的受击减伤保持原样。
6. **连段衰减保持原样。** 早期版本曾误改这一段，现已移除；连段伤害仍会正常递减。
7. **版本脆弱。** 地址与字节绑定具体版本，换版本会安全拒绝（不会误写），需要重新对位。
8. **可能触发杀软。** 工具会 `OpenProcess` + `WriteProcessMemory`，属调试器行为，加白名单即可。它只操作游戏进程。
9. **仅单机。** 不要在联机对战中使用。
10. **不修改任何文件。** 游戏 EXE 与 Data 目录始终原样，可随时用 MD5 校验。

## 常见问题

**Q：`kof.cmd install` 报"落地指令字节与预期不符"？**

上次残留状态或版本不匹配。先直接再执行一次 `install`（会自动修复失效跳转）；仍报错说明版本不同，跑 `kof.cmd doctor` 把输出发到 Issues。

**Q：`kof.cmd` 提示"未找到可用的 Python 3"？**

Python 未安装或未进 PATH。装好 python.org 版本（勾选 Add to PATH）后**重开命令行**。仍不行就用绝对路径调用：

```bat
"C:\Path\To\python.exe" src\hookdmg.py install
```

**Q：提示 `AttributeError: class must define a '_type_' attribute`？**

Python 环境的 `_ctypes.pyd` 与解释器版本不匹配（多见于自动更新过程中）。按顺序：再跑一次 → 换另一个解释器（`py -3` / `python`）→ 重装 Python。

**Q：开了 `on` 但伤害没变化？**

按顺序查：① `kof.cmd show` 倍率是否 >1 且为"开"；② 是否在 1P 位置、打的是电脑；③ 是否在 `install` 之前就 `on` 了；④ 游戏是否在这次操作后重启过（需重新 `install`）。

**Q：杀毒软件报警？**

加白名单或临时放行。程序只读写游戏进程内存，不联网、不落地文件（日志除外）。

**Q：游戏窗口总是自动最小化？**

本作失去前台焦点会自我最小化，属正常行为，点回前台即可，与工具无关。

**Q：能不能一次性永久生效？**

不能，改动在内存中，关掉游戏就没了。但不必每次手敲命令——用 `kof.cmd launch`，一条命令完成"启动 + 打补丁"，想更省事就把它做成桌面快捷方式（工作目录设成仓库根目录）。

**Q：`kof.cmd launch` 说找不到游戏？**

三档兜底依次是：`config.json` 的 `game_exe` → Steam 库自动扫描（读注册表里的 Steam 路径和 `libraryfolders.vdf`）→ 工具所在目录及其上一级。都不中就手动指定一次：

```bat
kof.cmd launch --exe "D:\Games\THE KING OF FIGHTERS 2002 UM\KingOfFighters2002UM.exe"
```

或者把上面的路径写进 `config.json` 的 `game_exe`，以后直接 `kof.cmd launch`。

**Q：`launch` 启动了但补丁没打上？**

看它打印到哪一步：卡在"等待引擎解密"是游戏还没加载完（加大 `--timeout`）；提示"补丁写入后被覆盖"通常是版本不一致，跑 `kof.cmd doctor` 把输出发 Issues。直接起 exe 没反应的话，加 `--steam` 改走 Steam 协议。

**Q：会不会被 Steam 判定为作弊？**

它不改文件、不联网，仅本机内存。但本作是单机向移植，请勿用于任何联机场景。
